2. El error de "Address already in use" en el puerto 8005 va a volver a aparecer tarde o temprano

Ese error del primer intento fue el puerto de apagado (shutdown) de Tomcat, que por default es 8005 — y tu IdentityIQ (/opt/tomcat) también usa ese mismo default, porque nunca se tocó su server.xml. Dos Tomcats separados en el mismo servidor compitiendo por el mismo puerto 8005 es una condición de carrera esperando a pasar otra vez (que esta vez no chocara fue cuestión de timing, no que el conflicto ya no exista). Cámbiaselo al del Cloud Gateway para que no dependa de la suerte:

bash
cd /opt/cloudgateway/apache-tomcat-9.0.104/bin
sudo -u tomcat JAVA_HOME=$(dirname $(dirname $(readlink -f $(which java)))) ./shutdown.sh
sudo sed -i 's/<Server port="8005" shutdown="SHUTDOWN">/<Server port="8006" shutdown="SHUTDOWN">/' /opt/cloudgateway/apache-tomcat-9.0.104/conf/server.xml
3. Deja el JAVA_HOME permanente (para no tener que escribirlo cada vez)

Tomcat lee automáticamente bin/setenv.sh si existe — así no dependes de acordarte de anteponer JAVA_HOME=... cada vez que arranques o apagues:

bash
sudo tee /opt/cloudgateway/apache-tomcat-9.0.104/bin/setenv.sh <<'EOF'
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-17.0.19.0.10-2.el9.x86_64
EOF
sudo chown tomcat:tomcat /opt/cloudgateway/apache-tomcat-9.0.104/bin/setenv.sh
sudo chmod +x /opt/cloudgateway/apache-tomcat-9.0.104/bin/setenv.sh

Ahora arranca ya de forma simple (sin anteponer nada):

bash
sudo -u tomcat /opt/cloudgateway/apache-tomcat-9.0.104/bin/startup.sh
sleep 3
ps -ef | grep -i cloudgateway
sudo tail -20 /opt/cloudgateway/apache-tomcat-9.0.104/logs/catalina.out
curl -k -I https://localhost:8443

Debe mostrar Using JRE_HOME: con la ruta real (ya sin anteponer nada tú) y el curl debe regresar un HTTP/1.1 200 o similar (no Connection refused).
