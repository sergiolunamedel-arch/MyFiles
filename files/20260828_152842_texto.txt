1
Crear Password Policy
Definir el objeto Password Policy en IdentityIQ con las reglas de complejidad, longitud, historial y expiración que deben cumplir las contraseñas.
2
Habilitar features PASSWORD y UNLOCK por aplicación
En la definición de cada aplicación (AD, Google) marcar el soporte tanto de cambio de contraseña como de desbloqueo de cuenta, y mapear los atributos correspondientes para cada una.
3
Configurar el canal real para cada acción
Para AD: ambas acciones pasan por el IQService (LDAPS), pero requieren permisos delegados distintos en la cuenta de servicio — 'Reset/Change Password' para el cambio y 'Unlock a user's account' para el desbloqueo. Para Google: el cambio usa la Admin SDK Directory API; el desbloqueo hay que validarlo aparte, ya que Google maneja suspensión de cuenta en vez de lockout por intentos fallidos.
4
Definir Password Sync (si aplica)
Decidir si un cambio de contraseña debe propagarse automáticamente a AD y Google a la vez. El desbloqueo normalmente no se sincroniza, ya que cada aplicación maneja su propio estado de bloqueo.
5
Activar Lifecycle Manager - Manage Passwords y Unlock Account
Habilitar ambos módulos en LCM y asignar los QuickLinks 'Change Password', 'Forgot Password' y 'Unlock Account' a la QuickLink Population correspondiente.
6
Configurar preguntas de autenticación
Necesarias para el flujo self-service 'Forgot Password', ya que el usuario aún no tiene sesión iniciada en ese punto.
7
Configurar plantillas de notificación
Correos de confirmación y de error tanto para cambio de contraseña como para desbloqueo de cuenta.
8
Pruebas end-to-end
Probar cambio de contraseña y desbloqueo por separado contra AD; validar si el desbloqueo aplica o no para Google.
