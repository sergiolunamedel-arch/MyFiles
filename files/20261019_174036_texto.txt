Prueba 1 (solo lectura, Linux, prompt $): compara el Java de Tomcat con el de la consola.

bash
ps -u tomcat -o args= | grep -o '^/[^ ]*java' | sort -u
sudo -u tomcat bash -c 'readlink -f "$(command -v java)"; java -version 2>&1 | head -1'

Si el segundo comando da error por bash, usa sudo -u tomcat java -version. Dime las rutas de Java que aparezcan en cada uno. Si son distintas, ahí está la diferencia.

Cómo leer la prueba 2

Sin errores (resultado committed) y sin entrada nueva en IQTrace.log: el canal funciona desde Tomcat. El fallo era de la JVM de la consola, y el workflow o QuickLink propio funcionará. Entonces sí te bloqueo de nuevo para la prueba real.
Mismo Connection reset y otro handshake en el log: el problema es del TLS entre el conector y el IQService, no de la consola. Entonces revisamos cómo está configurado el IQService (versión de TLS, certificado) frente a la app de AD.
